OpenHands SDK 深度精读：工业级 coding agent 的分层

OpenHands Team, 2025 · arXiv 2511.03690

为什么是 OpenHands

它不是论文，而是工程报告：把 agent 拆成可以独立测试、独立替换的部件——controller、agent、runtime、skills、observation。这种「部件解耦」是工业级 agent 与研究原型的根本差别。

Controller：step → action → observation 循环

controller 负责 driver loop：把 task 给 agent，agent 返回 action（bash/edit/browse/...），controller 在 runtime 里执行，把结果包装成 observation 给 agent。整个 loop 有超时、预算、retry、interrupt。

Runtime：docker 化 sandbox

每次任务起一个独立容器；文件系统、网络、进程都被隔离；skills 通过事件源（event-sourced）与 runtime 通信，便于审计与回放。是 L13 安全设计的具体落地。

Skills：可调用 Python 函数式技能

AgentSkills 把「打开文件」「运行测试」「读 issue」等封装成带 schema 的函数，让模型像调 tool call 一样调它们。比直接给 bash 更可控，比 GUI 更抽象。

Observation 的类型化

CmdOutputObservation / BrowserObservation / AgentStateObservation：每种 env 反馈结构化成一个类型，便于 controller 做 retry/终止判断、监控做行为簇分类（L15 Hodoscope 类工作）。

附 · OpenHands 部件分层图

controller 管循环，runtime 做 sandbox，skills 提供工具，observation 类型化回写——四层解耦才能独立测试与替换。

怎么读它

不要当论文读，当「设计图」读。对着它的 controller-runtime-agent-skill 分层，问自己：你的 agent 项目里 controller 是谁？runtime 是不是 docker？skills 是不是函数？observation 是不是类型化？四层缺一层，工程就不完整。
