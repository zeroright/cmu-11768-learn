Building Effective Agents 深度精读：Anthropic 的工程经验

Anthropic Engineering, Dec 2024

workflow vs agent

workflow 是预设代码路径（deterministic pipeline），agent 是让 LLM 自主决定下一步。Anthropic 强调：能用 workflow 就别用 agent——agent 是「当 workflow 撑不起来时的最后手段」。这条原则反直觉但极其重要。

五种 workflow 模式

prompt chaining（子任务串行）/ routing（分类到不同 handler）/ parallelization（同时多调用再合并）/ orchestrator-workers（分解 + 委派）/ evaluator-optimizer（生成 + 反思改进）。这五种覆盖了 80% 的实际场景。

autonomous agent 何时才需要

当任务真的无法预知下一步（如开放探索、长程问题、多轮交互），才需要 agent。Anthropic 建议：(1) 用「agent loop = LLM + tool + env」的最小骨架；(2) 让 env 提供清晰反馈；(3) 让模型能停止；(4) 给监控留好 hook。

工程细节

文档建议关注 tool design（简单清晰 > 强大复杂）、error message（让错误可读）、budget guardrail（不要无界循环）、human oversight（关键决策人介入）。这些细节决定了 agent 能不能生产化。

对 L15 编排监控的连接

workflow 模式对应 LangGraph/状态机；agent 部分对应 L14 OpenHands；监控部分对应 L15 Hodoscope/Docent。Building Effective Agents 是把三者连起来的工程总纲。

怎么读它

这是工业界最有影响力的 agent 工程文。读它不要记「workflow vs agent」的术语，要记「先 workflow，后 agent，agent 留 human oversight」的取舍逻辑。
