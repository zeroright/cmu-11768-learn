ReAct 深度精读：语言模型如何边想边做

Yao et al., ICLR 2023 · arXiv 2210.03629

问题：CoT 是『想完再做』，agent 需要『边想边做』

纯粹的 Chain-of-Thought 让模型先在脑内生成完整推理，再输出一个动作；但 agent 的环境是异步的——你得先调一次工具看到结果，才能决定下一步。ReAct 的关键是把 Thought、Action、Observation 交织成一条序列，让模型在每一步重新决定「要不要继续想」「要不要换一个工具」「要不要收尾回答」。

方法：把推理轨迹变成 prompt 编程

作者把 ReAct 实现为 few-shot prompt：给模型看几个 Thought/Action/Observation 的样例，让它续写。Action 就是一段可解析的调用（如 search[entity]、lookup[keyword]、finish[answer]），Observation 是工具的返回。这个设计的精妙之处是——不需要训练，只需要 prompt 工程，就能把一个 LLM 变成 agent。

实验：在 HotpotQA 与 FEVER 上的对比

ReAct vs 纯 CoT vs 纯 Act（只动作不思考）：ReAct 显著领先，特别是在需要多跳推理的问题上；但「绝对性能」仍依赖工具返回质量。一个反直觉的发现是，ReAct 的 hallucination 比 CoT 更少——因为它把推理建立在真实的工具返回上，而不是纯靠 parametric knowledge。

ALFWorld 与 WebShop：从文本到具身

论文还把 ReAct 用在文字冒险游戏（ALFWorld）和网购模拟（WebShop）上，分别比模仿学习/RL 基线提升 34% 和 10%。这证明 ReAct 不仅是 QA 的提示技巧，而是通用的 agent 决策骨架。

局限与今天的边界

ReAct 的成功前提是：(1) 工具返回是文本、可进 prompt；(2) 单轨迹、无回溯；(3) 靠 in-context learning 而不是训练。今天的 ReAct 衍生（如 Plan-and-Execute、Reflexion、LATS）分别在「计划显式化」「失败反思」「搜索树扩展」三个维度扩展它，但底层骨架仍然是 Thought-Action-Observation。

怎么读它

如果你只读一篇 agent 论文，读 ReAct。它的贡献不是某个具体算法，而是给出了一个能写进任何系统的『通用 agent 循环』。读它时关注三件事：Action 是怎么定义的？Observation 怎么进 prompt？失败时怎么重试？
