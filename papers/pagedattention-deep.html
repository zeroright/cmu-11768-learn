PagedAttention 深度精读：vLLM 如何把 KV cache 当页表管

Kwon et al., SOSP 2023 · arXiv 2309.06180

问题：KV cache 是 LLM 服务的最大内存瓶颈

每个 token 的 KV cache 占几 KB，一条 4k 上下文的请求可能占数十 MB；传统做法给每个请求预留 max_len 连续显存，导致利用率只有 20-40%。这意味着 GPU 大部分显存被「可能用不到的空间」占用。

类比：OS 的虚拟内存

PagedAttention 的核心洞察是「KV cache 就像进程的虚拟内存」——不需要物理连续，只需要逻辑连续。把 KV cache 切成固定大小的 block（默认 16 token/block），用 block table 做逻辑→物理映射，按需分配。

copy-on-write：beam search 与 parallel sampling 的优化

当多个 beam 共享前缀时，物理 block 共享同一份内存；只有分叉后才复制新 block。这让 sampling n 个候选的成本几乎等于单条请求——这对测试时算力缩放（L02）至关重要。

调度：continuous batching + PagedAttention 一起用

vLLM 把「哪个请求正在跑」与「它的 KV 在哪个 block」解耦：prefill/decode 按 step 进 batch，请求完成就释放 block 给下一个。这是 OS 调度思想在 LLM 上的复用。

数据：吞吐提升 2-4×，TTFT 几乎不变

论文报告在 OPT-13B/LLaMA-13B 上，vLLM 相比 FasterTransformer 与 Orca 提升 2-4× throughput；延迟（TTFT/ITL）基本持平。今天 vLLM/SGLang 是事实标准，PagedAttention 是它们的内存核心。

对 agent 的影响

agent 任务的 trajectory 是长 context + 多轮 KV cache 增长，且需要并行 rollout；PagedAttention 直接决定了「同一张 GPU 能同时跑多少个 agent trajectory」。L12 的 RL 系统讨论都建立在它的基础上。
